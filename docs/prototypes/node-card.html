What the card is for

  1. It's for reading. It answers "what is this, and what does it touch?" at a glance, and it never scrolls. Anything longer is one click away, and that click replaces the card's contents (with a back arrow) instead of growing it.
  2. One line, not a paragraph. The context shows as a one-line summary. You can edit it, or ask the AI to write the summary from the full context; neither is open by default.
  3. Connections first. What calls this and what it calls are the most useful thing on the card. Every one is clickable: it goes to that thing (selecting it opens its card).
  4. Counts instead of contents. References, libraries, notes and comments show as a count. Reading them is for when you want to, and for the canvas's layers. Nothing that's empty takes up space.
  5. Easy to reset. Click off the node and back onto it, and the card is at its top again. It doesn't remember which sub-view you were in.
  6. The same frame for every kind. The header, summary and connections are always in the same place. Each kind changes only its middle: tech for an app, tables for a store, file and signature for a function, version and users for a library, both ends for a connection.

Sources these lean on: progressive disclosure (show what's common first, the rest on request: NN/g); Retool moving rare fields into a hidden panel when they simplified their inspector; Apple's guidance that an inspector follows the selection and keeps rare or dangerous things low (inspector guidelines); and IcePanel users asking for a wider detail panel, because long descriptions are hard to read in a narrow one.

A: read, then drill in. A 380px card in three parts: header, one-line summary, and what it connects to. Below that, one row each for references, notes and comments, with a count. A row opens its list in place of the card (back arrow to return), so the card never scrolls. Recommended: it's the smallest change from today, and it works the same for every kind.

A, adding things. The same card, while you're filling it in. Everything is typed in place: no dialogs, no forms, no Save button. Enter keeps a field and moves on, Tab skips it, Esc leaves the card, and an empty field shows as one faint line, not a box. Try it: the card below is a box you just put on the canvas.

1 · Make it: name, one line, tech

Dropping a box opens its card with the name already focused. Enter goes to the one-line summary, then to tech. Tech suggestions come from what's already in the design, and from the name ("…Worker" suggests the queue you use elsewhere). That's the whole required part: three lines.

2 · Connect it by typing

"Connect to…" looks up names as you type, nearest first: same system, then on this diagram, then everything. The arrow button (or Tab) flips the direction. Picking one adds the row and puts you on its label ("what for"), which shows on the arrow. Dragging from a box's edge to another box does the same thing, and lands on that same label.

3 · Paste anything to reference it

One field for every kind of reference, which works out what you gave it: a URL becomes a link (docs sites get a docs badge), repo:path becomes code, .md a doc, an image an image, and react@18 or cargo:axum a library. The badge shows before you press Enter, so a wrong guess is visible. Pasting onto the card anywhere does the same.

4 · Editing later is the same fields

On a filled card these are the read view: clicking the name or the summary line turns it back into this field, in place. The pencil opens the full context (with ✦ summarise). Rows you've added get a ✕ on hover. Nothing reflows while you type, so the card doesn't jump.

Notes and comments stay out of the way

They aren't fields on the card. A note is a row ("Notes 1 ›") once it exists; you add one from the row, or with N on the canvas like today.

A, adding by kind. Each kind asks first for the one thing it can't be made without, then gets out of the way. Enter on the first field makes it and puts you back on the canvas. Tab goes on to what's optional. ⌘Enter makes it and drops the next one of the same kind beside it, for jotting down a lot quickly. Everything else (notes, references, connections) has its own route, so nothing is asked up front. Pick a kind and try it; the keys are the toolbar's.

A, adding to a node. Everything you hang on a box is added from that box's card, never from a separate panel. Each row opens with its own input at the top, made for what goes there, and the list under it. Empty rows aren't shown: the "+" chips at the bottom open the same view for the first one. Only on an entity's own view are entities made at the top level, like boxes. Click around: every input works.

Tags

For ownership and the like (team-orders, owner:sam, pci). They work like references: a shared list, Tab completes, a new one is just made. On the canvas each tag is its own small sub-node, and hovering it lights every box with that tag.

Also on N diagrams

The footer's left button. It opens a short list of the diagrams this box is on: where each lives, and how many of its connections are drawn there. Click one (or arrows and Enter) to jump there with the box selected.

Entities

Type a name: suggestions are the design's entities (and where each is defined). Picking one points at it. A new name goes straight into its fields grid, defined here. Each entity has a source, the node it lives in: one defined elsewhere says "from Mobile App ↗" (one click to go there), and its editor has Move here to make this node its source. Name : Parent extends. Making one with just a click (TBD) is only for typing a type in a function's inputs.

References

One field that works out what you paste (link, docs, code, doc, image), with the badge before you press Enter. Images can also be dropped in.

Libraries

A package: axum, react@18, cargo:sqlx. Suggestions are libraries already in the design first (so the spiderweb joins up), then the registries.

Notes

Just text. Enter adds it, Shift+Enter for a new line. Newest first, with who and when.

Comments

A thread, pinned to the box on the canvas. @ suggests people. Same Enter rules as notes.

Connections

"Connect to…" with the arrow for direction (from the adding page): picking one adds it and puts you on its label.

B: tabs. The same header and summary, then tabs: Overview, Connections, References, Notes. The card is a fixed height, and each tab shows what fits, plus "Show all on the canvas" (which turns on that layer). It's easy to scan which tabs have something, but tabs hide the connections behind a click, and connections are the main thing.

C: wide, with its neighbours. A 600px card that reads like a page. Left: the summary and its facts. Right: a small map of what calls in and what it calls out, each one clickable. References, notes and comments become counts along the bottom that turn on their layer. The best for reading, but it covers more of the canvas.
