A third section in the left pane, next to Views and Flows. A Code entry is a repo (the design's linked repo, or several), with its crates or packages under it. Opening one shows this page: the tree, the call graph, the libraries.
  • Ways in: pick it in the left pane; Enter on a code component in a diagram (Board hub → its crate); a function reference an agent pasted (s-chan:…#post_message) opens it selected, with the lens up.
  • Ways out: a function's "Runs in" chip goes back to that box on the architecture views; a flow under Flows can step through the code here.
  • Open questions: one entry per repo, or per running component? Is a code view saved like a diagram (which functions are on it), or always generated from the folder you pick?

What this changes

  • No new drawing kind for calls. A function is a box (kind: function) in its file, a file in its folder; the process frame is a boundary (where it runs), like the host frames we have. A call is a connection. Everything atlas does with boxes works here.
  • The tree is the model's own in tree, shown as files. Clicking a file or folder frames those boxes; the blue dot marks what's on this view. Messy code stays honest: main() lives in one file but its calls reach three processes.
  • Across repos and services: a box from another repo or an outside caller (the Claude Code harness here) is just a box in another frame, connected the same way.
  • Flows are separate: atlas's existing flows, stepping over these connections. Here they only light the path; no numbers, no animation.
  • Depth: a view of a folder shows its files' functions; closing a file in the tree folds its functions into the file box, and the calls move to it (the nearest-box rule).
